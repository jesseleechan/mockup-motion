# Stack plan: Desktop Stack and Mobile Stack

**Status: decided; S01 next.** Written 18 October 2026. The owner answered D1–D7 the same day: "all as recommended".

On 18 October 2026 the owner reviewed five preset proposals with live previews ([shortlist](https://claude.ai/artifact/Sh1TVUML9ToqKKfWmSNC9Y)) and approved four, each built in its own session. This plan covers one pair:

| Preset            | What it does                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Desktop Stack** | A deck of flat landscape cards. Each step the front card leaves the frame and the deck moves forward one card. Back cards peek out along the axis of motion. |
| **Mobile Stack**  | The same deck with mobile screenshots on portrait cards (the Mobile Slider card: phone screen aspect 0.4615, 7.5% corner radius).                            |

Same house style as the other presets: Ash `#DFE1E3` or Onyx `#141417` through the Light/Dark switch, frameless cards, no shadow, grain 0, vignette 0, no tilt, a still camera, and a native loop with a cut wrap. [`reference.md`](reference.md) has the measured reference (Rico Stack 2) and every way it differs from the approved preview.

## 1. What has to be built

The deck has the sliders' timing: one step per screenshot, 2.0 s per step, a 1.85 s move on the `slide` easing (`sliderStep`, `SLIDER_MOVE_DURATION` in `src/motion/layouts/slider.ts`), then a hold. A shot lasts N × step. After N steps every card is back where it started, so frame(0) ≡ frame(total).

**Geometry (the preview's numbers; starting points to tune on the contact sheet, then recorded in quality bar §4):**

- Depth: the front card plus up to two behind, `depth = min(3, N − 1)` cards in view at rest. During a step one more shows: the leaving card. With N = 3 that is 3 distinct screenshots, so none appears twice in view.
- The card `r` slots back is scaled `1 − 0.06 r` and offset along the axis by `r × peek`: peek = 0.12 × card height (desktop, peeking below) or 0.20 × card width (mobile, peeking right), so its bottom or right edge shows.
- Desktop card height = min(0.84 × W / 1.6, 0.8 / (1 + (depth − 1) × 0.12)); mobile card width = min(0.7 × 0.4615, 0.86 × W / (1 + (depth − 1) × 0.2)), where W is the frame width in stage units.
- The whole deck (front card plus peeks) is centred. The front card leaves up (desktop) or left (mobile) until it is 0.03 stage units past the frame edge, on the same progress as the deck.
- The card entering the last visible slot fades in during the step, paired with its scale and move (quality bar §2.5), through `DeviceFadePass` (`src/engine/devices/DeviceFade.ts`) as the slider does.
- Back cards at full colour (D1) and the screen is exact on every card once settled.

**Engine.** A `stack` layout exists (`src/motion/layouts/stack.ts`), but it is a static tilted fan of browsers that no template builds since 8 October 2026 (`docs/plan/follow-ups.md`: "No template builds the stack layout any more… Decide whether to keep stack"). D4 picks the model; the recommended one (§3) makes the deck an arrangement of the `slider` layout, so the step timing, the 30 s cap, the still camera, the Step control, the screenshot list, the drop-to-replace and the sRGB fade all carry over with no new branches.

## 3. Why the deck goes on `slider` (D4)

Three options were weighed:

- **A deck mode on `stack`** (`stack.mode: "deck"`). It reuses a name that fits, but nothing else: `stack`'s fields (`device`, `spread`) mean nothing to a deck, and the deck needs the slider's `axis`, `shape` and `step`. Every place that treats a slider specially today (about 20: duration, still camera, the Step control, the screenshot list and its cap, the media drop, the sRGB fade in `Engine.ts`, the sanitizer and user templates) would need a second `kind === "stack" && mode === "deck"` branch.
- **A new `deck` kind.** Clean in `types.ts`, but it duplicates the same 20 branches.
- **`arrangement: "deck"` on `slider` (recommended).** The deck _is_ a slider with a different arrangement of the same ring: the same steps, the same `slide` curve, the same native loop, the same card shapes. `resolveSliderLayout` dispatches on the arrangement to a new `deck.ts` for the geometry; everything else is shared. Unset means carousel, so no saved project or baseline changes. The inspector's Layout section gains no new section; the template sets the arrangement.

The Orbit session also builds on the slider's step timing. If it adds an arrangement too, the field is additive (`"carousel" | "deck" | …`) and the two PRs merge by keeping both values.

- The owner has signed off on the S04 contact sheet and approved the new baselines. CI's `unit`, `e2e` and `visual` are green.
